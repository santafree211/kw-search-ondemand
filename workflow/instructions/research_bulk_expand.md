# Module: research_bulk_expand

## 1. 責務（Single Responsibility）
複数のシードキーワードを受け取り、Ubersuggest APIの推奨シード数（1回あたり1〜3語）に合わせて自動的に**小バッチ（チャンク）に分割**して順次 `match_keywords` を呼び出す。
1回のAPIコールで最大50件、全バッチ合算で数百〜千件規模の関連キーワードと月間検索ボリューム（`search_volume` / `volume`）を一括取得・集約する。
集約した生データから、ローカルプログラムが `volume >= 1900` のキーワードを自動抽出し、実測ボリュームキャッシュ（`verified_volume_cache.json`）にアトミックに一括保存する。
スプレッドシート既存登録済みキーワードを除外した「即戦力当たりKW候補リスト」を返却する。

## 2. APIトークン節約効果
- **単発方式（従来）**: 50キーワードのボリューム検証に **50枠** 消費。
- **バルクバッチ方式（新）**: 1バッチ（シード2語）につき最大50語が **1枠** で検証完了（**98%削減 / 50倍高効率化**）。
- 大量シード（例: 20個）の場合でも、10回のAPIコールで最大500キーワードを全件スクリーニング可能。

## 3. 入力引数
- `SeedKeywords`: 展開の起点となるシードキーワード配列（1〜無制限）
- `BatchSize`: 1リクエストに含めるシード数（デフォルト: 2、推奨: 1〜3）
- `MaxBatches`: 実行する最大バッチ数（デフォルト: 0=無制限）
- `DelayMs`: バッチ間の待機ミリ秒（デフォルト: 500ms）
- `MinVolume`: 下限月間検索ボリューム（デフォルト: 1900）
- `Limit`: 1バッチあたりの取得最大件数（デフォルト: 50）
- `LocId`: 地域ID（デフォルト: 2392 / 日本）
- `Language`: 言語コード（デフォルト: "ja"）
- `Excludes`: 除外キーワード配列（スプレッドシート既存KW等）
- `DryRun`: APIを呼び出さずキャッシュまたはモックから検証するスイッチ

## 4. 出力仕様
- `Status`: 実行結果ステータス（Success, PartialExhausted, DryRun等）
- `TotalBatches`: 実行された総バッチ数
- `CandidateKeywords`: ボリューム1,900以上で未登録の当たりKW候補一覧
- `TotalFetched`: APIから一括取得された総キーワード数
- `PassedVolumeThreshold`: ボリューム基準を満たしたキーワード数
- `NewCacheEntries`: 新規にキャッシュへ記録されたキーワード数

## 5. ガードレール・安全設計
- バッチ実行の途中でAPI上限（HTTP 403 / Daily reports limit reached）に遭遇した場合は、即座にループを安全中断し、**それまでに取得した全データを失わずにキャッシュ保存**して、`Status = "PartialExhausted"` として返すこと。
- 取得したボリューム数値を手動で書き換えたり推測で補正することは絶対禁止（第6条）。
